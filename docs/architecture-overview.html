1 · System context

Who talks to this service, and what it talks to.

The service never talks to a target system directly — every attempt is delegated through the connector framework's leased facade, which owns retries at the transport level, breakers, and pooling.

3 · Operation lifecycle

Every enqueued mutation moves through this state machine exactly once.

Three non-terminal states, four terminal outcomes. The four-way split at finalize (success / rejected-before-dispatch / confirmed failure / indeterminate) is the load-bearing design decision in this codebase — each implies a different, specific remedy.

4 · Data model — the partitioned operation table

Why the hot table stays small regardless of throughput.

Default retention: 24 hours hot. Everything that ever finalized is kept forever in the slim, unpartitioned operations_history table (id, instance, class, type, status, uid, error code, timestamps — no payload).
